## Original promises and ownership

| Baseline contract | Review interpretation |
| --- | --- |
| Localization combines GNSS, wheel, IMU, and a noisy UAV-relative observation; publishes one authoritative map pose and covariance. | The EKF, frame/covariance math, correction matching, and public pose adapter belong here. |
| The relative-observation interface is independent of sensing technology. Tags, UWB, and camera tracking are possibilities, not commitments. The subsystem explicitly excludes perception. | A camera producer can be an integration fixture or another subsystem's component; making it a permanent responsibility of the estimator is scope expansion. |
| `uav_control` owns the PX4/UAV ROS interface and exposes state needed to interpret relative observations. | PX4 state subscriptions, reference-reset handling, and anchor publication need that owner. Localization consumes the shared anchor and may retain numerical conversion helpers. |
| Integration owns worlds/models and shared message architecture; fault/evaluation owns fault injection and the project test matrix. | Focused localization tests are promised and appropriate. Embedding reusable simulation/fault machinery in the normal estimator path creates an ownership overlap. |
| Raw UGV sensor bridging, TF ownership, and exact noise/rates are open decisions. | Assigning the UGV bridge to localization is a decision to document, not a proven violation of an established owner. Shared `/clock` ownership still needs an explicit integration decision. |
| Planner and downstream navigation use the authoritative fused pose. | Updating `route_planning` and `ugv_control` to consume it fulfills the contract. Changes outside the localization directory are not automatically scope creep. |
| Estimation tolerates missing, degraded, stale, and rejected measurements; relevant evaluation includes downstream path-following error. | Sensor validity and uncertainty must survive adaptation. Final goal distance alone does not measure route tracking. |

## Findings requiring approval

- **P1:** incorrect operational behavior or loss of an operational node. **P2:** integration, evidence, ownership, or validation defect. **P3:** maintainability issue.
- **Reproduced:** exercised against reviewed source. **Inspection:** confirmed from code/contracts; no full simulation trial is claimed. **Known gap:** already acknowledged in current docs, retained here because it remains relevant.
- A scope finding recommends moving responsibility or making a fixture explicit; it does not recommend deleting useful tests or reverting necessary integration.

| F01 · P1 · Bug · Reproduced | **Clock rewind crashes the UAV correction node.** [`uav_correction.py`](../../ros2_ws/src/cooperative_localization/scripts/uav_correction.py), lines 67–75 and 121–125: `process()` fixes its loop count, but `valid_time()` clears the pending deque inside that loop. The existing tests miss this queued-reset case. | Localization: handle clock reset before iterating; return after clearing state or process a detached batch safely. Add a regression with multiple pending readings and verify recovery after rewind. |
| F02 · P1 · Bug / contract gap · Reproduced | **Degraded GNSS uncertainty is discarded.** [`ugv_measurements.py`](../../ros2_ws/src/cooperative_localization/scripts/ugv_measurements.py), lines 261–282, ignores `NavSatFix.position_covariance` and its type; a known 100 m² x variance becomes 2.25 m² with default settings. | F03 · P1 · Bug · Reproduced | **Unavailable IMU orientation becomes a precise heading measurement.** [`ugv_measurements.py`](../../ros2_ws/src/cooperative_localization/scripts/ugv_measurements.py), lines 225–260, ignores the `orientation_covariance[0] == -1` unavailable marker and quaternion validity. A zero quaternion with unavailable orientation produces a normal output quaternion and yaw variance 0.0004 rad². | The EKF is configured to fuse absolute IMU yaw. Missing heading can therefore become a confident artificial zero-heading observation rather than leaving that state unmeasured. | Localization: preserve unavailable-component markers, validate finite/unit orientation and vector values, and publish valid turn-rate data separately when orientation is unavailable. Test missing orientation, malformed quaternion, and invalid sensor components. |
| F04 · P1 · Bug · Reproduced | **A delayed path for the previous goal can authorize motion.** [`goal_controller.cpp`](../../ros2_ws/src/ugv_control/src/goal_controller.cpp), lines 32–46 and 69–87: changing the goal clears the cached path, but any subsequent fresh path is accepted without association to that goal. The UGV can resume along an obsolete mission route after a goal change. | Planning/control owners: associate paths with a goal revision/request identifier and reject obsolete revisions. | F05 · P2 · Scoring bug · Reproduced | **Arrival can pass before its stop-duration check completes.** [`score_goal_navigation.py`](../../scripts/score_goal_navigation.py), lines 132–145, sets `stopped_at` on the first qualifying stopped sample, but the final pass expression only requires it to be non-null.
